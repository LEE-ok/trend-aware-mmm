# M3: 광고 예산 배분 설계 및 제약 검증

`/simulator/`는 총예산과 5개 채널 비중으로 배분 금액을 계산하고 운영 제약을 검사합니다.
Bayesian MMM 매출 예측은 실행하지 않습니다. 기존 정적 export와 M0~M2 UI를 유지합니다.

## 데이터 계약과 기본값

- `data/dashboard-aggregates.json`은 전체 209주 집계이며, 정확한 최근 13주 예산 총액은 없습니다.
  전체 기간 합계를 기본 예산으로 사용하지 않습니다.
- `data/mmm-results.json`의 문서 기록값 `budget_million_usd: 16.2`를 사용합니다.
  기본값 16,200,000 USD는 `docs/scenario.md`의 약 16.20M에 근거한 값입니다.
  정확한 원본 집계로 표현하지 않습니다. 기간은 13주로 고정합니다.
- S0 비중: DM 25.82 / SO 13.21 / VIDTR 9.61 / VIDDIG 1.08 / SEM 50.28 (%).
- 운영 경계 프리셋: DM 5.1 / SO 4.1 / VIDTR 31.1 / VIDDIG 8.2 / SEM 51.4 (%).
  문서 반올림값 합계는 99.9%입니다. 정확한 내부 배분값은 미확보 상태이며,
  특정 채널에 0.1%p를 추가하거나 비중을 정규화하지 않습니다. 직접 보정하도록 안내합니다.
- 프리셋 출처는 `document_recorded`이고 trace는 미검증입니다.
  사용자 계산값은 입력값을 이용한 산술 결과이며 모델 기록값과 구분합니다.
- 운영 경계는 M2 `trend_bounded.bounds_pct`를 설정으로 전달합니다.
  DM 5~60%, SO·VIDTR·SEM 0~60%, VIDDIG 0~8.3%입니다.
  이번 버전에는 제약 편집 UI를 추가하지 않습니다.

## 입력·산술 계산

- UI는 `components/budget-simulator.tsx`, 순수 계산은 `lib/simulator.ts`에 분리했습니다.
  서버 페이지가 JSON에서 예산·비중·경계만 추려 전달합니다. M2 매출·증분·확률은
  Simulator 클라이언트 설정에 전달하지 않습니다.
- 채널 입력은 0~100%, 소수 둘째 자리까지 지원합니다. 비중을 0.01% 정수로 저장해
  이진 부동소수점의 합계 오차를 피합니다. 문서 프리셋의 원래 값은 별도로 유지합니다.
- 예산은 0보다 큰 소수 둘째 자리까지의 USD로 받고, 최대 999,999,999,999.99 USD입니다.
  내부 금액은 BigInt 센트입니다. 빈 값·음수·NaN·Infinity·지수 표기·쉼표·초과 정밀도는
  오류를 표시하며 0으로 변환하지 않습니다. 입력 텍스트는 편집 중 그대로 유지합니다.
- 비중 합계와 100%의 차이, 채널별 제약 위반을 실시간 표시합니다.
  합계가 다르면 유효한 숫자의 금액은 임시 배분안으로 표시하며, 전체 예산으로 맞추지 않습니다.
  숫자 입력이 잘못되면 배분 금액 계산을 보류합니다. 비중 오류 시 차트도 보류합니다.
- 채널 금액의 소수 센트 잔여분이 큰 순서로 1센트씩 배분합니다(최대잔여법).
  동률은 문서의 DM·SO·VIDTR·VIDDIG·SEM 순서로 처리합니다.
  비중을 바꾸는 보정과 구분하여 화면에 설명합니다.
- 목표 금액은 `round(총예산 센트 × 실제 비중 합계 / 10000)`입니다.
  합계 100%에서는 채널 표시 금액 합계가 총예산과 센트까지 일치합니다.
  99.9% 프리셋은 기본 예산에서 16,183,800 USD를 배분하고 16,200 USD가 미배분됩니다.
- S0 금액 비교는 사용자가 입력한 동일 총예산에 S0 비중을 적용합니다.
  과거 집행액 대비 증감이 아닙니다. 채널별 비중 변화는 %p, 금액 증감은 USD입니다.
- 프리셋 버튼은 편집 중인 비중을 교체하고 총예산은 유지합니다.
  Reset은 비중과 총예산을 초기 S0 상태로 모두 복원합니다.

## 모델 미확보 상태

예상 매출·ROAS·80% 신용구간 계산 버튼은 비활성화합니다. trace, 완전한 summary,
trend 입력 파일이 없어 실제 모델 평가를 수행하지 않습니다. 예측을 0으로 채우거나,
M2의 +20.8%를 사용자 배분에 재사용하지 않습니다.
운영 제약 통과는 모델 성과·외삽 안전성 검증이 아닙니다. 특히 총예산을 바꾸면
같은 비중 제약이 과거 관측 지출 범위 준수를 보장하지 않습니다.
API·DB·Python 서버·외부 유료 서비스·새 패키지는 추가하지 않았습니다.

## 검증 명령

Node 24와 기존 Python 환경을 사용합니다. 빌드 후 테스트를 실행합니다.

```powershell
npm.cmd --prefix apps/web run typecheck
npm.cmd --prefix apps/web run lint
npm.cmd --prefix apps/web run build
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --experimental-strip-types --test apps/web/scripts/test_simulator.mjs
.venv\Scripts\python.exe -B apps/web/scripts/test_dashboard_data.py
.venv\Scripts\python.exe -B apps/web/scripts/test_m2_data.py
```

Node의 기존 package.json 모듈 유형 자동 감지 안내만 선택적으로 숨깁니다.
프로젝트의 모듈 설정은 바꾸지 않습니다. 해당 옵션을 생략해도 테스트는 통과합니다.
